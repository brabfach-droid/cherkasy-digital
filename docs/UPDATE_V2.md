# Оновлення до v2.0.0

1. Розпакуйте новий архів. На GitHub оновіть файли в корені репозиторію (де package.json), збережіть власні значення GitHub Variables.
2. У вже підключеному Supabase відкрийте SQL Editor і запустіть **тільки supabase/08_v2.sql**. Дані збережуться. Для нового проєкту використовуйте setup.sql, що вже містить V2.
3. Файл .github/workflows/deploy.yml залиште на GitHub. Якщо браузер відмовляє завантажувати приховані файли: Code → Add file → Create new file → назва .github/workflows/deploy.yml → вставте його текст → Commit changes.
4. Дочекайтеся зеленого Deploy GitHub Pages у Actions. Оновіть сайт Ctrl+F5. PWA оновлюється після закриття старих вкладок і повторного відкриття.

## Що додано

- Єдині motion tokens, короткі переходи сторінок, кнопок, карток, полів, рядків, сповіщень; анімовані modal open/close, accordion, toast, мобільне меню кабінету. Підтримка prefers-reduced-motion.
- Admin → Важливі оголошення: реальна верхня плашка, 6 типів, час початку/кінця, пріоритет, кнопка, версія, dismiss. Critical не закривається. Показується одна найважливіша плашка, інші доступні у списку.
- Дрібний номер версії у футері, також на /display й offline page.
- Розумні підказки біля поля після blur. Конструктор має noFuture і showWhen (точний ключ іншого поля й значення). Сервер повторно перевіряє правила; це не лише візуальна перевірка.
- /account/activity: власна хронологія подій із пагінацією. Старі зміни статусів імпортуються; події профілю/повідомлень/документів починають записуватися після міграції.
- Статус email береться із Supabase Auth. Інші підтвердження вносить адміністратор у розділі Підтвердження акаунтів після реальної ручної перевірки. Самопідтвердження через REST заборонено RLS.
- Notification inbox: типи, read/unread, прочитати всі, пагінація; dropdown дзвіночка; коротка одноразова реакція на нові непрочитані.
- QR у власній поданій заяві створює випадкове посилання з 64 hex символами. /status/:token показує лише номер, послугу, статус, дати. Власник може відкликати посилання. Публічна таблиця токенів недоступна.
- QR публічного документа веде на сторінку документа.
- Історія змін для послуг, новин, документів, FAQ, подій, оголошень. Окремі snapshots, поля зміни, порівняння та відновлення для дозволених ролей; RLS зберігає межі департаменту. Відновлення записується в аудит і створює нову версію. Для фізично видаленого запису відновлення недоступне.
- /display: годинник Kyiv, дата, міські статуси, оголошення, події, новини, послуги, QR, ручний fullscreen, пауза, плавна ротація. Critical зупиняє ротацію. Admin → Налаштування → Режим великого екрана (title, blocks у потрібному порядку, interval 5–120, theme, qr_url, fullscreen_friendly).
- PWA: manifest, PNG icons placeholders, service worker, offline fallback, ненав’язлива пропозиція встановлення. На iPhone встановлення доступне через Safari → Поділитися → На початковий екран.

## Межі офлайн

Кешуються лише allowlist статичних файлів збірки та offline.html. Supabase, підписані файли, API, приватні відповіді й дані заяв не кешуються service worker. Навігація офлайн показує окрему сторінку; актуальний статус тривоги доступний лише онлайн. Авторизація Supabase, як і раніше, використовує браузерне зберігання сесії — воно відокремлене від PWA-кешу. Розклад alerts.in.ua й токен з попереднього налаштування зберігаються.

## Після оновлення перевірте

Створіть тестове важливе оголошення, закрийте і підвищте його версію. Перевірте critical на /display. Подайте тестову заяву, створіть QR, відкрийте без входу й відкличте. Відредагуйте тестову новину та відновіть попередню версію. Перевірте встановлення PWA й offline fallback. SMTP, реальний alerts token, cron та hosted Storage потребують перевірки у вашому Supabase.
