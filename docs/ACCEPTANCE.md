# Перевірка після підключення

1. Відкрийте головну з ПК і телефона. Не має бути горизонтального скролу; burger відкриває й закриває меню.
2. Каталог: пошук, категорія, online/offline, аудиторія, доступність, сортування, reload зі збереженими query filters.
3. Зареєструйте мешканців A і B, підтвердьте email. Перевірте reload session, вихід, reset password за листом.
4. A: заповніть профіль, додайте адресу, приватний документ, збережіть послугу.
5. A: відкрийте демопослугу, заповніть поля, додайте тестовий PDF, збережіть чернетку. Поверніться через «Чернетки». Поля й файли мають зберегтися.
6. Надішліть заяву. Номер CK-YYYY-NNNNNN, статус «Подано», history й notification.
7. B не повинен побачити заяву A навіть за відомим UUID або приватним object path.
8. Зареєструйте operator O, призначте роль і департамент через super_admin. O бачить відповідну заявку, працівник іншого департаменту — ні.
9. O: прийняти → розгляд → потрібна інформація. Напишіть повідомлення й internal note. A бачить зовнішнє повідомлення, internal note не бачить.
10. A: відповісти, додати PDF. O: розгляд → схвалено → виконано. History і notifications оновлюються.
11. Viewer читає департаментну заявку, але не може змінити статус чи надіслати staff comment. Editor не читає заявки/профілі заявників.
12. Admin: створити категорію/послугу, schema form, опублікувати. Зміна форми не змінює snapshot уже поданої заяви.
13. Новина: Markdown headings/bold/list/link/image, preview. HTML `<script>` не виконується.
14. Документ: додати PDF, опублікувати, відкрити великий viewer, full modal, окреме відкриття. DOCX відкривається через кнопку.
15. Оголошення banner/modal/pinned, час початку/кінця. Матеріал scheduled не видно до його published_at.
16. Послугу/новину відправити до архіву/кошика і відновити як draft. Перевірити audit.
17. Звернення A: категорія, місце, текст, фото; staff отримує, передає, відповідає й завершує. B не читає звернення.
18. Admin: branding, footer, hero, homepage block order. Зміни відображаються після reload.
19. alerts: cron оновлює api_cache. Вимкніть token або job на тестовому проєкті: через 120 секунд frontend показує невідомий стан. Поверніть налаштування.
20. Через GitHub commit оновіть видимий текст. Дочекайтеся зеленого Actions deploy й перевірте прямі routes/reload та auth email links.

Не використовуйте реальні персональні документи для цих тестів. Демо-заява не є офіційною заявою до міської ради.
